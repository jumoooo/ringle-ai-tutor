## B. 멤버십

| # | 가정 | 이유 |
|---|---|---|
| B1 | 만료 판단은 expires_at < Time.current 단일 기준 | 세션 횟수 복잡도 제거 결정 |
| B2 | Free 플랜은 expires_at = 100.years.from_now (사실상 무기한) | trial 상태 처리 단순화 |
| B3 | 업그레이드 시 잔여 기간 이어받기 | max(expires_at, now) + duration_days |
| B4 | 다운그레이드는 API 없음 (어드민 삭제 후 재구매로 처리) | 요구사항 미명시 |
| B5 | 환불 API는 payment_log 기록 목적으로만 stub 구현 | 실결제 없음 |
| B6 | 어드민 멤버십 부여 시 기존 active/trial 멤버십은 expired로 교체 | 중첩 방지, 사용자 결정 |

## C. AI 파이프라인

| # | 가정 | 이유 |
|---|---|---|
| C1 | 빈 transcript는 서버에서 LLM으로 넘기지 않음 | 비용 낭비 방지 |
| C7 | 만료 감지는 클라이언트 타이머 (expires_at 기준 setTimeout). 폴링 없음 | 사용자 결정 |
| C8 | 1턴 = 유저 발화 1회 + AI 응답 1회. 최대 20턴 = 메시지 최대 40개 | 사용자 결정 |
| C9 | 유저 발화 오디오는 서버에 저장하지 않음. blob URL은 브라우저 메모리에만 유지 | 개인정보 최소화, 사용자 확인 |
| C2 | 한국어 입력 시 AI가 영어로 대화할 것을 요청하는 응답 | 요구사항의 "영어 대화"가 명시 목표 |
| C3 | 첫 AI 메시지는 conversation 생성 시 자동 생성 및 저장 | 대화 기록 일관성 |
| C4 | SSE 연결 끊김 시 클라이언트가 재연결 시도 (최대 3회) | 네트워크 불안정 대응 |
| C5 | TTS 실패해도 텍스트는 유지 (음성만 없음) | UX 저하 최소화 |
| C6 | 문장 분리는 [.?!] 기준. 중간에 "Mr.", "Dr." 등은 오검출 가능성 있으나 허용 | 구현 단순화 |

## H. 요구사항 원문 미명시 사항 — 자체 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 대화 언어 제한 | 영어만 (한국어 입력 시 안내) | 프로젝트 목적 (영어 회화 튜터) |
| 최대 턴 수 | 20턴 | 비용 제어 기본 안전장치 |
| TTS 속도 | 0.95 (자연스러운 속도) | 학습 목적 최적화 |
| VAD 무음 threshold | 1.5초 | 일반적인 발화 패턴 |
| 마이크 자동 OFF | 3분 | 배터리/마이크 보호 |
| 만료 폴링 주기 | 1분 | 과도한 요청 방지 vs 즉시성 균형 |
